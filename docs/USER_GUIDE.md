# Battery Tool Plus 使用指南

Apple Silicon MacBook 的电池循环与计算负载管理工具完整操作说明。回到[项目首页](../README.md)。

## 安装

从 [GitHub Releases](https://github.com/hcy2206/battery-tool-plus/releases) 下载 `BatteryToolPlus-<版本>-macos-arm64.dmg`，双击挂载后把 `Battery Tool Plus.app` 拖到 Applications。无需安装 Python 或 Xcode。

### 签名校验与打开

Release 提供对应源码归档和 `SHA256SUMS`，把两者放在同一目录即可校验：

```bash
shasum -a 256 -c SHA256SUMS
```

应用使用 ad-hoc 签名，没有 Developer ID，也没有经过 Apple 公证。首次打开时 macOS 会提示无法验证开发者：打开"系统设置 → 隐私与安全性"，在页面底部点"仍要打开"即可（[Apple 说明](https://support.apple.com/102445)）。不需要关闭 Gatekeeper。

或者在终端移除隔离扩展属性后直接打开：

```bash
xattr -dr com.apple.quarantine "/Applications/Battery Tool Plus.app"
```

### 系统要求

- Apple Silicon
- macOS 15 或更高版本

### 从源码构建

```bash
git clone https://github.com/hcy2206/battery-tool-plus.git
cd battery-tool-plus
./scripts/build-macos.sh
open "dist/Battery Tool Plus.app"
```

构建产物为 ad-hoc 签名的应用，直接可用。需要 Xcode Command Line Tools。

### 演示模式

演示模式只渲染界面和模拟模式切换，不写 SMC，也不运行负载：

```bash
open "dist/Battery Tool Plus.app" --args --demo
```

真实与演示模式的设置和历史分开保存；切换前先退出正在运行的应用。

### 本地修改后重新签名

自行修改并重新构建后，用同样的 ad-hoc 方式签名即可运行：

```bash
APP_PATH="/Applications/Battery Tool Plus.app"
codesign --force --deep --sign - "$APP_PATH"
codesign --verify --deep --strict --verbose=2 "$APP_PATH"
open "$APP_PATH"
```

## 快速开始

1. 打开主窗口。默认为系统管理，不自动恢复上次的任务。
2. 点击"授权电池控制"，完成一次管理员授权。图形应用本身以普通用户运行，不要用 sudo 启动。
3. 在"任务设置"调整电量上下限、健康度目标、CPU/GPU 档位和 CPU 线程数。参数在下次启动任务或切换到日常循环时生效；编辑过程中不影响运行中的任务。
4. 选择模式：
   - **系统管理**：应用默认状态，不控制电池。
   - **准备外出**：停止负载和强制放电，恢复正常充电，保持到你手动切换。
   - **日常循环**：在电量上下限之间充放电，不运行负载。
   - **定时压测**：在确认的窗口内循环，充电与放电阶段都运行设定负载。
5. 定时任务的目标时间在未来 24 小时内。截止目标有两种：
   - **到点开始使用电脑**：到点停止负载，转入日常循环。
   - **到点携带电脑离开**：按无负载充电记录估算所需充电时间，提前结束压测并转入准备外出，默认目标电量 100%。没有足够记录时使用你设定的预留时间（默认 120 分钟）。
6. 默认在使用电脑时暂停负载，持续空闲 300 秒后恢复，并且不超出已确认的窗口。关闭该选项可保持压测。手动暂停需要手动恢复。
7. "停止并交还系统管理"随时可用，立即停止负载并解除强制放电，即使设置表单里有无效输入。

关闭窗口后应用与菜单栏继续运行；退出应用会停止负载并恢复正常充电。应用不设置开机启动，也不在重启后自动恢复任务。

## 负载、温控与保护

- CPU 和 GPU 负载各自运行在独立的普通用户进程中，以 user-initiated QoS 调度，因此 CPU 负载落在性能核上。CPU 档位控制计算占空比；GPU 使用短批次 Metal 计算加批次间休息。档位是工作比例，不是系统占用率读数。
- 系统热状态 fair 时负载减半；serious/critical 时停止负载并允许充电，恢复后等待 60 秒再加载。macOS 温控始终优先。
- 拔电源、读数异常、达到目标健康度或电源写入失败时结束任务并恢复充电。电量低于 `max(3%, 充电下限/2)` 时结束压测并充电。允许充电十分钟后电量没有上升会给出提示。
- 允许充电但系统持续十分钟不充电（macOS 自身的充电上限或优化充电），当前电量即作为本轮上限，转入放电。
- "任务设置"页可填 PushDeer Key。只推送需要介入的情况：任务意外结束、恢复充电失败、睡眠通知风暴、达到目标健康度；相同内容 30 分钟内不重复。
- 历史记录写入失败只显示提示，不影响任务运行。

## 睡眠、合盖与显示器

- 定时任务期间阻止空闲系统睡眠；不阻止合盖或主动睡眠。放电阶段电源服务以 `pmset disablesleep 1` 禁止系统睡眠（含合盖睡眠），否则切断适配器后 macOS 会在几秒内合盖睡眠或按电池空闲计时睡眠，放电无法推进。恢复充电后等 IOKit 看到适配器并稳定 20 秒再还原原设置（立即还原会执行断电期间排队的合盖睡眠）；服务退出时同样处理。服务异常终止留下的禁止状态由下一次授权启动的服务清除。
- 日常循环与定时压测期间默认阻止显示器空闲熄屏（控制台开关可关闭）；命令行循环全程以 `caffeinate -d` 保持。合盖使用时，放电期间显示器一旦熄屏就无法用鼠标键盘点亮（macOS 只在有外接电源时点亮合盖模式的外接显示器），直到恢复充电。
- 睡眠前停止负载；3 秒内未再唤醒才恢复充电（合盖模式下其他进程频繁点屏会产生成对的睡眠/唤醒通知），睡眠期间继续向电源服务发送心跳，唤醒后重新检查截止时间。一分钟内的重复睡眠通知合并为一条历史事件；一分钟内 4 次以上视为"睡眠通知风暴"（多半是其他程序在频繁点亮显示器），此时负载不再随通知停止，控制台会显示状态，五分钟无通知后解除。
- 切断不影响雷雳/USB4 拓展坞与显示器的链路（PD 合同与端口控制器计数不变），拓展坞由自身电源供电。切断作用于整机的外部供电输入，不区分 MagSafe 与 USB-C 端口。
- 切断适配器后 IOKit 的 `ExternalConnected` 会变为 No，但适配器功率（`AdapterDetails.Watts`）仍在，因此"适配器已连接"按两者之一判断；只有真正拔掉电源才会结束任务。

## 空闲推荐与历史记录

在"空闲推荐"页开启本地记录（默认关闭）。开启后每 30 秒记录时间、活动/空闲、电量、充电与负载状态；不记录按键、窗口或应用名称。控制操作和错误事件始终记录。

- 保留最近 90 天；推荐使用最近 28 天，区分工作日与周末，近期数据权重更高。
- 以 15 分钟为时段、每个日期一票,至少 3 天观察且空闲比例达到 80% 的时段才会推荐；窗口提前 15 分钟收尾，并限制在 24 小时任务上限内。
- 数据不足时回退到你设定的初始空闲区间，支持跨午夜。推荐只在你确认后启动，不会自行扩大窗口。
- 应用未运行、睡眠和采集间断的时间记为未知，不当作空闲。温控暂停不会被当作用户活动。
- 没有键鼠输入的活动（看视频、开会）会被判断为空闲，需要时手动暂停。
- 历史页展示最近 24 小时电量曲线和最近 100 条事件，可一键清除。
- 数据位置：`~/Library/Application Support/BatteryTool/`；演示模式使用 `BatteryTool-Demo/`。

## 系统与固件支持

充电控制依赖固件暴露的 SMC 键，应用和 CLI 在运行时自动探测并选择：

| 系统 / 固件 | 充电抑制键 | 放电键 | 行为 |
| --- | --- | --- | --- |
| macOS 15.0–15.6 | `CH0B` / `CH0C` | `CH0I` | 放电阶段停充并切断适配器；充电阶段恢复 |
| macOS 15.7–26.6 | `CHTE` | `CHIE`（否则 `CH0J`） | 同上 |
| macOS 27，以及 15.8 / 26.7 更新后的固件 | 无（替代键需要 Apple 私有 entitlement，root 也不可用） | `CHIE` | 放电阶段切断适配器用电池供电；充电阶段恢复适配器正常充电。循环充放电完整可用，不支持"插电但停充"的保持状态 |

macOS 27 路径已在 M2 Max（固件 20457.1.29）上实机确认读数与 `CHIE` 可用；前两条路径沿用上游实现，由模拟后端的回归测试覆盖写入序列。

电量与健康度读数与系统一致：电量取电量计上报的百分比（IOKit `CurrentCapacity`/`MaxCapacity`，与菜单栏、`pmset -g batt` 相同），健康度取系统设置中的"最大容量"（通过 `system_profiler SPPowerDataType -json` 读取；该值由 powerd 自行计算，无法从公开键推出），读不到时回退为标称容量 ÷ 设计容量。

macOS 自身的充电上限（如系统设置中的 80% 限制或优化充电）可能把电量停在你设定的上限之下，且此固件没有可覆盖它的键。允许充电但系统持续 10 分钟不充电时，把当前电量作为本轮上限开始放电；要充到更高电量，请在系统设置中关闭该限制。

## 命令行（Python CLI）

```bash
uv tool install --python 3.12 --no-config .
sudo "$(command -v battery-tool)"
```

CLI 会直接写 SMC，需要 root；非 root 运行会明确提示使用 sudo。`--status` 只读取状态，不需要 root。开始循环前连接电源适配器。图形应用的电源服务与 CLI 使用同一把互斥锁，二者不会同时控制电池。

| 参数 | 作用 | 默认值 |
| --- | --- | --- |
| `--target-health` | 健康度降到该值时停止循环 | `79` |
| `--max-charge` | 电量达到该值时开始放电 | `95` |
| `--min-charge` | 电量降到该值时恢复充电 | `5` |
| `--interval` | 轮询间隔（秒） | `60` |
| `--log-file` | 同时把 JSON 日志写入文件 | 无 |
| `--status` | 读取状态后退出 | `False` |

约束：`0 <= target-health <= 100`、`1 <= min-charge < max-charge <= 100`、间隔至少 1 秒。CLI 启动时显式设置充电状态；拔电源、读数无效、SMC 写入失败或 Ctrl+C 都会停止循环并恢复充电。运行错误退出码 1，参数错误退出码 2。原生应用默认循环区间为 20%–90%，可在任务设置中调整。

## 安全模型

电源服务是按需授权的短生命周期 root 进程，只接受充电、强制放电、心跳和退出四个命令，并校验连接方的用户身份；不接受任意 SMC 键或 shell 命令。图形应用每 2 秒续租，失联 12 秒后服务恢复充电并退出。负载进程在 stdin 关闭或 15 秒无心跳后退出。图形应用与 Python CLI 共用 `/var/run/batterytool-control.lock`，同一时间只有一个控制器写电池。
